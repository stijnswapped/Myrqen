# Working brand: Myrqen

## Status

Myrqen is a working codename selected after a preliminary web collision screen. It is not legal trademark clearance. Keep every identifier centralized so a rename is mechanically safe.

## Working name

Display: Myrqen
Uppercase mark: MYRQEN
CLI/package stem: `myrqen`
Pronunciation guide: roughly "MIR-ken"

## Brand idea

Myrqen is the quiet security engineer already inside your coding agent: methodical, skeptical, evidence-driven, and easy to summon.

## Positioning line candidates

Internal only until brand review:
- "Security testing, inside your coding agent."
- "Run the pentest where you build."
- "Find it. Prove it. Fix it."

Avoid absolute claims such as "secure your app completely" or "find every vulnerability".

## Voice

Use:
- "Validated finding"
- "Needs review"
- "This check could not be completed"
- "Authorize this exact target"
- "This scan will stay local"

Avoid:
- "We hacked you"
- fake panic language;
- hacker movie jargon;
- shaming developers;
- implying no findings means secure;
- repeated infrastructure warnings.

## Naming architecture

Centralize:
- display name;
- CLI name;
- config folder stem;
- API user-agent;
- token/key prefixes;
- package scopes;
- app domains;
- report footer;
- analytics product name.

Do not scatter `myrqen` string literals through logic. Tests should support a temporary alternate brand constant to expose hard-coded assumptions.

## Visual mark direction

Do not create a final logo until name clearance. Direction for a future designer: compact angular aperture/checkpoint symbol that can live at 16px in a terminal/app sidebar, avoiding shields, padlocks, bugs, skulls, or copied security-brand shapes.
