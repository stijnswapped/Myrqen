# ADR 016: One source for report numbers, a recomputed verdict, and a line-independent baseline

Status: Accepted.

Context: every report format counted for itself. The HTML stat cards read `summary`, the overview prose counted findings, the Markdown table read `summary` with its own defaults, and SARIF counted nothing. The stat cards also animated up from zero, so a screenshot of a static-only run showed "Findings 7" beside prose that said fourteen. A run no agent drove printed "unknown" for the agent, which hid the most important caveat in the report: nothing in it had been verified. Users also asked for compliance references and for a way to tell new findings from known ones across runs.

Decision:

1. `packages/report/src/facts.ts` is the only place a report count, run attribution, duration, or timestamp is derived. `buildReport` writes `summary` with it, and every renderer (HTML, Markdown, SARIF, the verdict, the prose) reads it. Counts are printed, never animated. Cross-format tests read the numbers back out of each rendered artifact and hold them to it.
2. Every report opens with a verdict (`verdict.ts`): one line, the counts behind it, a next step, and at most three findings ranked by severity discounted by verification state, each with a paste-ready prompt. `buildReport` stores a copy in `report.verdict` for machine consumers, but renderers always recompute it from the findings they are given, because a stored verdict can name a finding a projection withholds. Projections drop the stored copy (they are allow-listed).
3. Run attribution: no named agent plus findings that all carry the `static-pass` tag means no agent drove the run, and the report says so ("No agent — static pass only") and tells the reader to run `/myrqen` inside their agent.
4. Compliance references live in one table keyed by category (`compliance.ts`): CWE, OWASP Top 10:2021 and 2025 (2025 is the released edition), and ASVS 4.0.3 / 5.0.0 requirement ids in ASVS's own versioned notation. Placements were checked against OWASP's published CWE lists and ASVS sources. A test reads every category literal from `packages/scan/src` and fails if one is unmapped.
5. The baseline is `.myrqen/baseline.json`, outside the git-ignored `sessions/` and `reports/` directories so it can be committed. Its fingerprint is category + normalised file + the sink the evidence names (title as fallback, numbers stripped) + normalised route; line numbers are excluded so a shifted file does not turn known findings into new ones. The file holds no evidence or code. `createBaseline`/`compareToBaseline`/`parseBaseline` are library functions; `myrqen baseline` and `session finish` are thin callers. SARIF uses `baselineState` (`new`/`unchanged`) only when a baseline was compared.

Consequence: the schema gains optional, additive fields (`finding.compliance`, `finding.baselineState`, `report.verdict`, `report.baseline`); older reports remain valid. A finding that moves within a file keeps its baseline identity; one whose sink, file, route, or category changes is treated as new, and the old one as gone. "Gone" is reported as not seen by this scan, never as verified fixed.
